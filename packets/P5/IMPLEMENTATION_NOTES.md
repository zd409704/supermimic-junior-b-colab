# CR-B2-1 implementation notes (P5-prep; reading choices, not PLAN changes)

PLAN `spikes/B2/PLAN.md` sha256 `5d1f26f776a3ea56c2becd3ec2fa2cf8e88bd62c43a20f79415a96e82a3da11d`. Each item names the PLAN clause, the open point, and what the code does. Nothing here changes a scoring input. Verdict-tool readings are in `spikes/B2/verdict/IMPLEMENTATION_NOTES.md`.

1. **§2.3 (b) sizing "by the frozen `matched_hidden` routine … with the enlarged input".** The frozen routine counts `MLPDecoder` instances, which cannot see the 29 extra inputs. `mlp_mind.mind_hidden` runs the frozen `mlp_baseline.matched_hidden` unchanged, with the module name `MLPDecoder` temporarily bound to `MLPMindDecoder`, so the frozen search loop counts the enlarged-input network. Result: hidden (376, 188, 94, 47), 467 491 params (+0.75% of 464 001). `mlp_matched` stays (384, 192, 96, 48), 468 317.
2. **§2.3 (b) class.** `MLPMindDecoder` subclasses the frozen `MLPDecoder` only so that the frozen `decoder_sidecar` records `mlp_hidden`. Its `__init__` builds the enlarged first layer directly and does not call the parent constructor, so no throw-away layer consumes the init RNG. The forward draws the mask once per call and uses it for both the zero-fill and the indicator.
3. **§2.3 (b) registration order.** `mlp_mind.register()` patches `train_entry.POLICY_ARMS` and `train_entry.build_decoder` (wrapper; the frozen factory is kept as `__wrapped__` and still builds every frozen arm). It refuses to run after `eval_entry` has been imported without the arm. `p5_train_entry.py`, `p5_eval_entry.py` and `perm_check.py` call it at import.
4. **§2.3 (c) one frozen call per checkpoint.** The frozen `eval_entry.run_upstream` evaluates `[0.0, *b2.mask_fracs]`. The wrapper passes a config copy whose `b2.mask_fracs` is `[0.1, 0.2, 0.1, 0.2, 0.1, 0.2]` (seeds 7100, 7100, 7101, 7101, 7102, 7102), so one frozen call runs mask 0.00 once and the six masked conditions. For it 400/800/1200 the list is empty (mask 0.00 only). `eval.out_dir` is set to the exec directory. The condition boundary is a shim around `eval_entry`'s `runpy.run_path` (the frozen call that runs the upstream script); it checks that the frozen `--out` name matches the scheduled f, re-seeds, and afterwards renames the JSON to `…_ms<seed>.json` and writes the stream files. A `SystemExit(0)` from the upstream script is passed through after the rename, as the frozen caller treats it as success.
5. **§2.3 (c) generator.** One `torch.Generator(device=<decoder device>)` per device, created lazily at the first draw of a condition and seeded with the condition's seed. A draw outside a condition raises. A call that passes its own `generator` goes to the frozen function and is not recorded (the frozen CPU smoke and the PERM masked variant use this). The mask-0.00 condition writes stream files with `calls = 0`, `k = 0`.
6. **§2.3 (c) recording.** Each draw is copied to the CPU (one small sync per control step). The stream is stored bit-packed; `sha256` covers the packed bytes.
7. **§6 PERM default TF32.** "TF32 at its default setting" = the two flags as found when `perm_check.py` starts. The gated value is computed with both flags off. Inputs z, obs and the permutations are drawn on the CPU (global CPU RNG seeded 0; `torch.Generator().manual_seed(100 + t)`), then moved to the decoder's device, so all checkpoints see the same inputs. The masked variant draws m once on the CPU with the frozen function and `manual_seed(7100)`.
8. **§4.1 step 0 before setup.** Staging runs before the tarball is unpacked, in bash only (`stat`, `sha256sum`, `cp -p`), with the §2.2 table embedded in the driver. `run.sh` writes the two driver scripts to `/content/p5_b2/` and the tarball copy to `/content/` before that; neither touches the P4 tree.
9. **§9.3 write scope.** Read as: in the P4 upstream tree the driver writes only `logs/b2mt_*`, `logs/b2idx_*` (trainer run dirs), `logs/eval/b2*` and `logs/attempts/b2*`, plus the same `uv sync` / motion-data / `csv_to_npz` setup as P4 (B0 PLAN §4.1, which PLAN §4.1 step 1 requires). Driver bookkeeping (meta, train logs, PERM logs, deviations, BLOCKED) goes to `/content/p5_b2/`, outside the P4 tree. The driver never runs `rm -rf` on the clone: an existing clone not at the pin, or a non-git `/content/SuperMimic-Reproduced`, is `BLOCKED.md plan_gap` with nothing modified.
10. **§4.1 step 1 CPU tests.** The frozen smoke is gated with the P4 14/3 rule (`cpu_test_mismatch`). The P5 prep tests are also run on the venue (`meta/cpu_test_p5.log`) and recorded only.
11. **§9.3 GPU.** The driver stops at setup with `BLOCKED.md plan_gap` if the GPU is not `NVIDIA GeForce RTX 4090`, before any eval or training spend (the verdict would be BLOCKED anyway, PLAN §7.3 row 1).
12. **§4.1 steps 2–5 order.** U evals in PLAN order; then PERM on all six staged checkpoints (attention = gate, mlp_matched = reported, PLAN §6); then the cells. Per completed attempt: evals at 400, 800, 1200 (mask 0.00), then 1600 (7 conditions), then PERM. A diverged attempt that completed is evaluated and PERM-checked, reported only (PLAN §4.2).
13. **§4.2 restart.** Session parts follow the P4 mechanism (`B2_STATE_IN`, `PART` records, `SPENT` hours). U evals and PERM are recorded in `driver_state.txt` and not repeated. An eval exec directory that already exists is never rerun; if it passes the file check it is used, otherwise the next exec number is used, never a third. An attempt interrupted before its `ATTEMPT` record would find its run directory present at the next part and stop with `plan_gap` (as P4).
14. **§10 spend cap.** 6 GPU wall-hours over all parts, checked before every new work item: each U eval, each U PERM check, and each new cell (review r1 #4). A started cell finishes, retries included ("stops after the current cell"). On reaching it the driver writes `SPEND_CAP_HIT`, `BLOCKED.md spend_cap` and packs; the verdict decides whether the required set was complete.
15. **Termination (review r1 #5).** `trap b2_abort TERM HUP INT`. Trainer, eval and PERM children are all waited for with `wait`, so the trap fires at once; it writes to the driver log (fd 3). The handler sends SIGTERM to an eval or PERM child (a non-interactive `&` job ignores SIGINT) and SIGINT to the trainer (restored by the CR-B0-1 launcher), each with 60 s grace then SIGKILL, stops the GPU-memory logger, classifies and archives the active attempt without `*.pt` and writes its `ATTEMPT` record (so a later part starts attempt N+1), records `SPENT`, writes `BLOCKED.md aborted` and packs. Exit code 143. Mock-checked during a U eval (`logs/p5prep/driver-mock-attempt4`) and during training (`…-attempt5`).
16. **§9.1 job JSON and runner stdout (review r1 #8).** These records belong to the relay. The upload list is the tarball and `run.sh` only (PS-B2-3), so the job JSON is not on the venue, and the runner's stdout cannot be inside the archive its own process writes. As in P4 (seal `RELAY-LOG`), both are deposited and sealed beside the archive by the relay. `run.sh` passes itself in `B2_EXTRA_FILES`. The driver's own stdout is `meta/driver.log`. A listed extra file that cannot be copied is recorded in `deviations.md`.
17. **§9.5 eval wall time (review r1 #9).** Each condition's wall time (`wall_s`, monotonic clock) and `start_utc` go to its `maskstream_<cond>.json` and to the `[p5_eval] maskstream …` line in `eval.log`, failed conditions included.
18. **Mock.** `packets/P5/mock/` (not in the tarball) runs the real driver functions on the box with a relocated `/content`, a fake trainer, a fake PERM script and a fake upstream package under the real `p5_eval_entry.py` and frozen `eval_entry.py`. It is plumbing evidence only, not evidence about B2.

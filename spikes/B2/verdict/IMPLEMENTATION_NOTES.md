# verdict_b2.py — implementation notes (ambiguities and literal readings)

Tool version 1.0. PLAN `spikes/B2/PLAN.md` sha256 `5d1f26f776a3ea56c2becd3ec2fa2cf8e88bd62c43a20f79415a96e82a3da11d`. Bundle layout: `packets/P5/BUNDLE_CONTRACT.md`.
Each item gives the PLAN section, the ambiguity, and what the tool does. Where an item says "as B0", the sealed `spikes/B0/verdict/verdict_b0.py` (`9caa744a…`) code is called unchanged, and `spikes/B0/verdict/IMPLEMENTATION_NOTES.md` gives the reading.

1. **Reuse of the B0 tool.** `verdict_b0.py` is loaded by path after its sha256 is checked (`9caa744a…`; mismatch = exit). Its module-level attempt-ID pattern is rebound in-process to `^(b2mt|b2idx)_(attention|mlp_mind)_s(\d+)_a(\d+)$`. Used unchanged: archive member checks and extraction, seal lookup, multi-deposit merge, tb reading (CRC, latest wall time wins), train-log parsing, the B0 §3.3 / §4.3 attempt classification and completion condition, tb metrics and the L-1 / L-2 windows, `v1_full`, `v1_integrity`, `v3_run`, `normalise_argv`, `check_eval_json`, `mask_metrics`, `ckpt_path_ok`. Notes items 1–5, 9, 10, 16, 21–23 and 30 of the B0 notes therefore apply here too.
2. **§4.2 scored attempt.** The scored attempt of a cell is the first attempt whose class is `completed` or `DIV` (a diverged attempt is final and is the cell's scored attempt; a completed one is scored whether or not it diverged). OOM or SEAM in a T cell is row 1. The INFRA cap is exhausted when the cell's first two attempts are both INFRA (row 1 for T, `cell_status` for `b2idx`).
3. **§4.2 diverged.** `diverged` = B0 §6.3 (a) evidence (non-finite tb scalar at step ≤ 1600, or an R-DIV final exception line before the endpoint), whatever the class. `t_status = diverged` if any scored T attempt diverged.
4. **§7.1 U-ID.** Checked in every opened deposit's own `meta/p4_ckpt_identity.txt` (each session part re-stages). Passes iff `root=` is one of the two literal PLAN §2.2 paths; for each of the six runs the `ls -l source` size of `ckpt_0001600.pt` equals §2.2, the `sha256 source` of `junior_policy.json` equals §2.2, the copy sha256 of both files under `/content/p5_p4ckpts/logs/<run>/` equals the source sha256, and `copy_equals_source=true`. `BLOCKED.md` `p4_ckpts_unavailable` is listed under `U-ID`.
5. **§7.1 U-REPRO.** The P4 reference files are read from `--p4-open-tree` and must match the 18 sha256 values of PLAN §5.4 (a mismatch makes U-REPRO false and the legacy table unavailable). Comparison: the P5 `mask0.00_ms0` JSON of the scored it-1600 exec vs the P4 `mask0.00` JSON; same set of 4 clip names; per clip equal `steps` and `failed`, and |Δ `norm_return`| ≤ 1e-4.
6. **§7.1 MS gate set.** The scored it-1600 execs of the 6 U runs and of every non-diverged scored T run. Reported separately (`gates.MS.reported`, never gating): the same plus scored `b2idx` runs and diverged-but-completed T runs. Per (f, seed) and run: both stream files present; JSON `seed` = condition seed and `frac` = f; packed shape (calls, 4, 4) and `rows_per_call` = 4; JSON `calls` = npz calls; sha256 of the packed bytes = JSON `sha256`; every row has exactly k set bits (3 / 6) and no pad bit set; `calls` = maximum clip `steps` of that condition's JSON. Pairwise, all runs' streams are byte-identical over their common prefix of calls. Nesting: within each run and seed, f = 0.10 bits ⊆ f = 0.20 bits over the two conditions' common prefix. The mask-0.00 stream (no draws expected) is not part of MS.
7. **npz reading.** Stdlib only: the `packed.npy` member of the zip is parsed as an `.npy` v1/v2/v3 file with dtype `u1`, C order.
8. **§7.1 B2-V-1.** Non-diverged scored T run: B0 `v1_full` (completed, no non-finite ≤ 1600, one tb file, logged point at 1600, `time/hours` and `time/updates` at 400/800/1200/1600, window coverage ≥ 10). Diverged scored T run: B0 `v1_integrity` (attempt dir, one tb file, train log, divergence evidence from that tb file or that log). A T cell with no scored attempt makes B2-V-1, B2-V-2, B2-V-3 and B2-V-4 false (row 1).
9. **§7.1 B2-V-2.** (a) tb `time/updates` at step 1600 = 624, non-diverged runs only (diverged: exempt). (b) The `[train_entry] upstream argv:` line, with `--run-name` and `--seed` and their values removed, equals the P4 attention s0 argv treated the same way. The P4 argv is embedded in the tool as a constant, copied from the sidecar `argv` of deposit `1f491182…` (sidecar sha256 `cc9cac58…`). (c) Every opened deposit's `meta/nvidia-smi.txt` GPU name is `NVIDIA GeForce RTX 4090`; otherwise row-1 item `gpu_mismatch` as well.
10. **§7.1 B2-V-3.** B0 `v3_run` seams (S1, S2 true; S3 recorded and consistent; no `unverified` line; attention arms also S4 = `env_init_state`, S5 true) plus: sidecar present; `policy` = arm; `train_mask_frac` 0.1 (`b2mt`) / 0.0 (`b2idx`); sidecar `attention.id_mode` `index` for `b2idx`, `morph` otherwise (the frozen sidecar records the config's `attention` block for every arm); attention arms' descriptor sha256 = `3c854f91…`; `mlp_mind` `params` within ±5% of 464 001 and `mlp_hidden` present. S3 must be identical across the scored T runs.
11. **§7.1 B2-V-4.** For each run and checkpoint the scored execution is the first of `exec1`, `exec2` with no content problem. Content: `eval.log` present; every `[eval_entry] … --ckpt <p>` line names the expected checkpoint (U: path ending `p5_p4ckpts/logs/<run>/ckpt_0001600.pt`, i.e. the staged copy; new runs: `logs/<RUN>/ckpt_<IT>.pt`); the number of `[eval_entry]` lines equals the number of conditions (7 or 1); each condition JSON `<run>_<arm>_mask<f>_ms<seed>.json` exists and passes the B0 JSON content checks; no un-renamed `…_mask<f>.json` is left. `exec3` or higher is never scored and is reported as a problem. The `exit=` line is recorded, not gated (as B0 note 10). Required: the 6 U runs at it 1600; non-diverged scored T runs at 400/800/1200 (mask 0) and 1600 (7 conditions). Diverged T runs are exempt.
12. **§7.1 PERM.** Gate checkpoints: `b2u_b0_attention_s{0,1,2}_a1` and every non-diverged scored `b2mt` attention attempt. Pass iff `meta/perm_<ID>.json` exists, `rel_err_tf32off` is finite and < 1e-4, and `auto_mask_frac_used` = 0.0. The `pass` and `role` fields written by the script are recorded but not trusted. A missing PERM file on a gate checkpoint makes PERM false (row 2), unless row 1 applies (for example the spend cap was hit before the required set was complete). Everything else with a PERM file is reported.
13. **§7.3 required set / spend cap.** Complete iff all 6 U runs have a scored it-1600 exec, all gate PERM files exist, and every T cell has a scored attempt that is diverged or has complete scored evals. The spend cap counts as hit if `meta/session.txt` says so, `driver_state.txt` has `SPEND_CAP_HIT`, or `BLOCKED.md` has `spend_cap`. Row-1 item `spend_cap` only when the cap was hit and the set is incomplete.
14. **§7.3 row 1, other items.** `plan_sha_mismatch` (the `--plan` file is not the sealed PLAN), `deposit_check` (unsealed / unextractable deposit, member check, `meta/tarball_sha256.txt` ≠ `--tarball-sha`, `BLOCKED.md` `tarball_sha_mismatch`), `R1_unresolved`, `venue_mismatch` (any venue other than `xn4090` in `--venue`, `meta/session.txt` or the seal line; PLAN §9.3 pre-registers XN-4090-GPU2 only), `blocked_md:<code>` for other `BLOCKED.md` codes (`plan_gap`, `setup_failed`, `cpu_test_mismatch`), `rho_undefined:<ID>`.
15. **§5.1–5.3 statistics.** R_H, R_step, Cum and survival per condition as B0 (`mask_metrics`). R_H(run, f) and R_step(run, f) are the means over the 3 mask seeds; ρ_H = R_H(f)/R_H(0) and ρ_step = R_step(f)/R_step(0) from the same exec; ρ*_H = (R_H(f) − 0.0393)/(R_H(0) − 0.0393), null if the denominator ≤ 0.01. Arm means and SDs (ddof 1) over the scored seeds; SE = √(s_a²/n_a + s_b²/n_b), null with fewer than 2 values in an arm. A null per-run value makes the arm aggregate null.
16. **§7.2 margins and shadows.** g_U = max(0.17, 2·SE_U(0.20)), g_T = max(0.10, 2·SE_T(0.20)). Shadow outcomes use the same table with Δρ_step and ΔR_H (absolute), each with max(floor, 2·its own SE) and the same floors. Shadows are computed only in row 4 (null otherwise); a null shadow input gives a null shadow. `metric_disagreement` is true iff some non-null shadow differs from `b2_outcome`.
17. **§7.3 T aggregates when diverged.** `t.f*` aggregates are null and the harness line prints `drho_t=null g_t=null`. `t_partial` gives the same aggregates over the non-diverged T runs with complete evals, when each arm has n ≥ 2; it never enters §7.2.
18. **§7.4 ablation.** The comparator "P4 attention" is the three P4 attention checkpoints as re-evaluated in P5 (the U runs), so both sides use the P5 eval path and mask stream. `ablation_status = complete` iff all 3 `b2idx` cells have a scored, non-diverged attempt with complete evals (all 4 checkpoints). Aggregates are computed over those runs when n ≥ 2. Labels only when complete.
19. **§8 gate.** `b0_outcome` is read from `--p4-results` only if its sha256 is `76507d8a…`; otherwise it is null and `gate_b1 = HumanLead`. `NONINFERIOR` (or `SUPERIOR`) → `Go`. `caveat_required` = (`b2_outcome` ≠ ROBUSTNESS_GAIN) or `u_deficit` or verdict ≠ PASS.
20. **§5.5 legacy table.** Recomputed from the sha-checked P4 files, labelled `mask_pairing = unverified_global_rng`. `delta_*_2se` is 2 × SE of the 3 + 3 seed means.
21. **§9.4 output.** Floats are printed with Python `repr`, `None` as `null`, lists comma-joined without spaces (as B0). `runs.<ID>` holds the B0 attempt fields for new runs, plus `condition`, `perm` and the B2 `eval` block; U runs hold `ckpt_identity` (per deposit), `repro`, `perm` and `eval`.
22. **§4.2 exec2 authorization (review r1 #2, settled in r3).** exec2 is authorized iff exec1 exists and either its `eval.log` records a final `exit=` that is non-zero, or exec1 lacks an expected condition or stream file. An exec1 with every file and no `exit=` record does not authorize exec2. exec2 without exec1, an unauthorized exec2 and any `exec3`+ make the checkpoint's history invalid: no scored exec (B2-V-4 false). The driver applies the same rule and writes `exit=<code>` for an eval it interrupts.
23. **§4.2 attempt history.** a1..aN contiguous, at most 2, only INFRA followed by another attempt; a violation leaves the cell unscored (`attempt_history`, row 1 for T, `cell_status` for b2idx).
24. **Aborted sessions (review r3).** `BLOCKED.md aborted` is provenance only (`aborted_deposits`). The evidence gates and the spend-cap rule decide the verdict, so an abort never changes it by itself.
25. **Robustness.** Malformed mask-stream files (any exception while reading) are MS problems; a PERM file that is not a JSON object fails PERM (gate) or is reported; non-finite values are written as null, and their paths are listed in `nonfinite_values_nulled`.

# verdict_b1.py + b1arms_driver.sh — implementation notes (literal readings)

Tool version 1.0. PLAN `spikes/B1/PLAN.md` sha256 `1088752ba26a8798d721aa93d6e10d1b7bdb7fb924d9d72879acc78d8c2304c8`. Written by the Orchestrator (PLAN §9 "infra code" slot) in P6d-arms-prereqs, before any arms deposit exists. Each item gives the PLAN section, the gap or ambiguity, and what the code does. None changes a metric, threshold, seed count, attempt cap or pass rule.

1. **§6 B1-V-5 vs §8 `*.csv` exclusion.** §6 names the `nvidia-smi … --format=csv` capture; §8 excludes `*.csv` from the bundle (the B1-RT bundle lost `meta/gpu_used.csv` this way). The driver keeps `meta/gpu_used.csv` and writes a byte copy `meta/gpu_used.csv.txt`; the verdict reads the copy. GPU memory traces are written as `.txt` for the same reason.
2. **B1-V-5 parse.** Header must be `index, uuid, name`; exactly one device row; its third field, stripped, must equal `NVIDIA GeForce RTX 4090` exactly. Every `meta/gpu_env.txt` line must end `CUDA_VISIBLE_DEVICES=0`. Per-attempt lines in `meta/gpu_used_attempts.txt`, if present, must also name that GPU. Other host rows (`nvidia-smi_part<n>.txt`) are kept and not checked.
3. **§3 harness stop (B0 PLAN §4.3).** It is copied from `packets/P4/b0_driver.sh` (launcher + harness_stop): SIGINT after the `it 1600 |` line plus two size polls of `ckpt_0001600.pt` 30 s apart, 300 s wait, SIGKILL only after `harness_stop_timeout`. The trainer may log a few iterations past 1600 during the 30 s poll window, as in P4. The endpoint is still `ckpt_0001600.pt`, and every metric uses that checkpoint and TB step 1600.
4. **B1-V-1 "completed".** Completed means all of: the train log has a line starting `it 1600 |`; the harness record has `ckpt_stable=true` for `logs/<RUN>/ckpt_0001600.pt`, no `harness_stop_timeout=true`, and sidecar not `missing`; `logs/attempts/<AID>/junior_policy.json` is present; at least one TB file exists; and no TB scalar is non-finite at step ≤ 1600 (§7: a non-finite run counts as not completed). TB duplicates are resolved by "latest wall time wins" (B0 reader). After that, seams S1/S2/S5 must be literally `true` and all 10 R_k must be finite.
5. **§7 scored attempt.** Attempt 1 if it is completed. Otherwise attempt 2, but only if attempt 1 is INFRA: not completed, not non-finite, not stopped by the spend cap. Attempts above 2, or an attempt 2 after a completed / non-finite / spend-cap attempt 1, are ignored and noted. The driver uses the same classes (`b1arms_helper.py classify`).
6. **§7 session loss across job launches.** On launch 2 (`B1ARMS_RESUME=1`), an attempt file with no `ATTEMPT` record is a session loss. If the trainer had already been classified COMPLETED (the loss came during evals), the missing eval points are run and the training is not repeated. An exec dir left by the lost part counts as a used execution, so a point whose exec1 was lost gets exactly one re-execution. Otherwise the lost attempt is INFRA and the next attempt starts in a fresh run dir. The spend clock carries over from the last `SPENT` record.
7. **§5 re-execution.** exec2 is scored only when exec1 has no `exit=0` line or does not hold exactly the expected `<RUN>_ckpt_<IT>_mask0.00.json`. An exec2 next to a valid exec1 is ignored and noted. R_k = `summary.mean_norm_return` of the scored JSON.
8. **§5 AULC/R25/R100.** These are computed as written: AULC = (1/9) Σ_{k=1}^{9} (R_k+R_{k+1})/2; R25 = R_2 + (400−320)/160·(R_3−R_2); R100 = R_10. Means use the arm's 3 seeds. The sample s.d. uses ddof = 1. SE = sqrt(s_X²/n_X + s_Y²/n_Y), with n = 3 in every PASS case (the PLAN's /3).
9. **§5 outcome.** Rules are applied in the written order with exact float comparisons, and KILL is tested first. If mean(H-A-scratch) ≤ 0, the 1.2× test is replaced by the absolute 0.2·|mean| test (`ratio_branch=abs_0.2`).
10. **§6 "any failure → BLOCKED"; B1-V-1 "partial seeds … INCONCLUSIVE at best".** If any check fails, `verdict=BLOCKED` and `outcome=null`. `partial_outcome` is filled when every primary arm has at least 2 seeds with full curves: SIGNAL / SIGNAL_STRONG are capped to INCONCLUSIVE, and INCONCLUSIVE / KILL are reported as computed. It is informational only and never a pass.
11. **B1-V-2.** Every primary run needs the it-1600 endpoint and `time/updates` at TB step 1600, and the 9 values must be equal. A primary run that is missing fails V-2 as well as V-1 ("every primary run"). The upstream argv in the sidecar, without `--run-name` and `--seed`, must be identical across the 9 runs and include `--env.num-envs 512`. This is the env-step part of the check: 512 env steps per iteration.
12. **B1-V-3 scope.** The check covers every xfer/frozen run that has a sidecar, diagnostics included (H-A-frozen, H-A-xfer-noscale), using the scored attempt or else the latest attempt with a sidecar. A secondary or diagnostic run that never started (cap room, source mismatch) is listed `not_run` and not failed. A primary run that never started fails. "All decoder parameters loaded" = `kind=attention_full_copy`, `n_params_copied > 0` and `n_values_copied == params_total` (decoder numel). The mlp check is `output_rows_mapped == 20` and `fresh_joints` = {head_yaw_joint, head_pitch_joint}. `init` in the sidecar must equal the arm's init.
13. **§4 source check.** Before each xfer/frozen attempt, the driver hashes `logs/b0_<policy>_s<k>/ckpt_0001600.pt` under the read-only roots `/content/p5_p4ckpts`, `/content/SuperMimic-Reproduced` and `/data/muchuan/p4-b0-attempt1/workdir/SuperMimic-Reproduced`, in that order. It uses the first file whose sha256 equals the §4 identity. If none matches, that run is blocked (`RUNDONE SRC_MISMATCH`, `BLOCKED.md src_ckpt_mismatch`) and the schedule continues. The file identity is the hash, so choosing by hash is not runner choice.
14. **§4 "secondary runs start only if the cap leaves room for a whole run plus its evals".** Room = elapsed + max measured duration (train + evals) of a completed run in this job ≤ 9.0 h. With no measurement there is no room. A skipped secondary is `SKIPPED_NO_ROOM`, which is not a spend-cap hit and does not write `BLOCKED.md`. Primary runs start whenever elapsed < 9.0 h.
15. **§7 spend cap.** The clock is driver wall time from driver start, setup included, summed over job parts. At 9.0 h during training (before the endpoint line), the trainer gets SIGINT (B0 stop procedure). During evals, the running eval gets SIGINT through `timeout`, and no new eval or run starts. The driver then writes `BLOCKED.md spend_cap` and bundles. A cap hit only in secondary or diagnostic runs leaves the primary verdict unaffected (§5: those arms have no role). `BLOCKED.md` lines are reported in `blocked_md` and do not gate by themselves.
16. **§8 deposit check.** A deposit is opened only if a `logs/seal.log` line has `DEPOSIT xn4090` with its sha256. Members are checked and extracted with the sealed B0 helpers (`spikes/B0/verdict/verdict_b0.py`, sha256 verified at import): no absolute or `..` paths, no `*.pt`, no escaping links, `tarfile` filter `data`. Every `meta/tarball_sha256.txt` part must equal `--tarball-sha`. Any failure adds `deposit_check` to `failing_ids` and forces BLOCKED.
17. **Mock.** `B1ARMS_MOCK=1` replaces only trainer / eval / tbdump (`packets/P6/b1arms_mock/mock_entry.py`, not in the tarball). The tarball / manifest / PLAN checks, order, harness stop, cap, attempts, source check and bundle run unchanged. The `B1ARMS_MOCK_*` overrides (cap, poll, source shas) are read only when `B1ARMS_MOCK=1`.
